1. 基础#

1.1 原理#

当web应用向后台数据库传递SQL语句进行数据库操作时，如果对用户输入的参数没有经过严格的过滤处理，那么攻击者就可以构造特殊的SQL语句，直接输入数据库引擎执行，获取或修改数据库中的数据。

1.2 产生条件#

  • 动态拼接字符串
  • 用户能控制输入的内容
  • 把用户输入的内容带入到数据库执行
  • 缺乏参数化、输入校验
  • 数据库账号权限
  • 可观察（内容、错误、时间等）

1.3 本质#

  • 代码中执行的SQL语句存在可控变量
  • 数据与代码边界被打破

4. 注入方式#

4.1 联合查询注入#

回显型 SQL 注入，让数据库把两条 SELECT 的结果集合并返回，并让其中一部分内容被前端渲染出来。
条件

  • 列数必须一致
  • 数据类型必须兼容

4.2 报错注入#

回显型注入，通过数据库抛出的错误信息带出数据
条件

  • 页面/接口会把数据库错误信息返回给客户端
  • 注入点能影响 SQL 语句结构

4.3 布尔盲注#

面不直接回显查询结果，也不一定报错，通过构造一个条件表达式，让页面表现出两种可区分状态（True/False），再用这些“是/否”推断数据。

4.4 时间盲注#

页面既不回显结果，也没有稳定的 True/False 内容差异，让数据库在条件为真时额外延迟（sleep / heavy computation / wait），再用响应耗时判断 True/False，从而推断数据。

4.5 堆叠注入#

通过结束符同时执行多条sql语句

4.6 二次注入#

恶意数据存储在数据库后，恶意数据被读取并进入到SQL查询语句导致

6. 防御与加固#

6.1 预编译（prepared statements）#

将 SQL 结构 与 数据 完全分离，SQL 在执行前已被数据库编译，参数只作为“值”绑定

6.2 输入验证与白名单#

  • 数字型参数：只允许数字，且限定范围
  • 枚举值：只允许固定集合（如状态、类型、排序字段）
  • 字符串：限制长度、字符集、格式（如正则）

6.3 最小权限原则#

区分读写账号，禁止应用账号有（CREATE / DROP / ALTER） 权限，生产环境禁root、直连

6.4 禁止错误回显#

关闭数据库详细错误输出，应用层统一错误响应

7.数据库基础（MySQL）#

7.1 数据库层次结构#

  • 数据库（Database）：一整个 Excel 文件，如：shop_db、crm、test
  • 表（Table）：文件里的每一个工作表，如：users、orders、logs
  • 列（Column、字段）：表里的每一列，描述某一类属性，如：id、username、password、email、created_at
  • 行（Row、记录）：每一行是一条具体的数据，如：用户表中的一位具体用户的信息

7.2 用户与权限#

  • 数据库用户（DB User）：root@localhost、app_user@%
  • 权限：
    • 库级：访问某个库
    • 表级：访问某个表
    • 操作级：SELECT、INSERT、UPDATE、DELETE、CREATE、DROP、ALTER、GRANT

7.3 MySQL特性#

7.3.1 语法特点#

大小写不敏感：

  • 大小写不敏感：select / SELECT / SeLeCt 在 MySQL 中均可执行 多种注释方式：
  • -- 空格 后面到行尾：单行注释
  • # 后面到行尾：单行注释
  • /* ... */：块注释，可跨行

7.3.2 元数据#

MySQL 会在系统库中保存所有库、表、列等信息

  • information_schema.SCHEMATA：记录数据库
  • information_schema.TABLES：各数据库对应的表
  • information_schema.COLUMNS：各表对应的字段

7.3.3 错误信息#

  • 语法错误位置
  • 期望的语法、实际出现的内容
  • 如果应用端把错误原样返回给前端，表名 / 字段名 / 部分数据 / SQL 结构 都可能暴露
  • sql_mode对注入和过滤的影响

7.3.4 字符集与编码#

  • 过滤 + 编码不一致
  • 多层转码：浏览器 → Web 框架 → 数据库驱动

7.3.5 内置函数丰富#

  • 字符串函数：CONCAT、SUBSTRING、HEX 等
  • 条件函数：IF、CASE WHEN
  • 时间函数、加减函数等
  • 特定版本：如 LOAD_FILE() 等
